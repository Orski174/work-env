# pg-ha-boxman-trial

Created: 2026-08-07 · Tracks scds-infra #91 (sprint-011), "CNPG using Boxman".

## Goal

Evaluate whether an HA Postgres setup — Patroni, on plain boxman VMs, using
CNPG's own Postgres container image as the base — is worth adopting over
today's per-service standalone Postgres containers (matrix_synapse,
vaultwarden, GitLab, ...), each of which has **no HA at all** today.

## Why not CNPG/k8s directly

CNPG (CloudNativePG) is a Kubernetes-native operator: its HA/failover logic
lives in the operator + the k8s API, neither of which exists outside a
cluster. The ticket's own named non-k8s fallback is **Patroni** doing HA
orchestration directly, reusing CNPG's Postgres image
(`ghcr.io/cloudnative-pg/postgresql:16`) as the container base rather than
building the trial around a bare `postgres:16` image.

## Where this runs

Authored on the workstation, **executed on `sc1` (scds001)** — a RHEL 9.7 box
with KVM + libvirt where boxman provisions the VMs. Workflow: edit here →
`git push` → `git pull` on sc1 → run there.

## External repos / dependencies

- **boxman** — `~/git/boxman` on sc1, conda env `boxman`
  (`~/.conda/envs/boxman/bin/boxman`).

## Layout

```text
boxman/conf.yml         1 template + cluster of 3 VMs (pg1, pg2, pg3), one nat1 net
patroni/
  Dockerfile             FROM ghcr.io/cloudnative-pg/postgresql:16 + patroni[etcd3]
  docker-compose.yml     etcd + patroni services, network_mode: host
  patroni.yml.tmpl       templated, rendered per node by setup.sh
  entrypoint.sh          exec patroni /etc/patroni.yml
  rendered/              per-node patroni.yml + .env (gitignored, generated by setup.sh)
setup.sh                 post-provision: docker fallback, push assets, build image,
                          render config, bring up etcd quorum then pg1 -> pg2/pg3
run.sh                   driver: up/setup/status/ssh/failover-test/backup-test/destroy
notes.md                 running log + measured results
```

## How to run (on sc1)

```bash
cd ~/git/work-env/tasks/2026-08-07-pg-ha-boxman-trial

./run.sh up                          # provision the 3 VMs
./run.sh setup                       # docker + patroni + etcd stack, all 3 nodes
./run.sh status                      # boxman ps + patronictl list

./run.sh failover-test --switchover  # graceful, controlled handover
./run.sh failover-test --kill-leader # hard-failure simulation (stop + rejoin)
./run.sh backup-test                 # pg_dump/restore round-trip + pg_basebackup check

./run.sh destroy                     # tear the lab down
```
